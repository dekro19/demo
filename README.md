# Regex-детектив

Из архива пропала папка дела №17. Изучите журнал пропусков, перехватите маршрут, обезличьте отчёт и восстановите события. Каждое решение даёт улику. Четыре улики складываются в финал расследования.

## Запуск и правила

Распакуйте ZIP, откройте терминал в папке проекта и запустите игру. Нужен Python 3.9 или новее. В игре и тестах используется стандартная библиотека.

```text
python -X utf8 main.py
```

В Windows можно заменить команду `python` на `py -3`, если установлен Python Launcher.

На приглашение `regex>` введите выражение как есть, например `[A-Z]{3}`. Кавычки и обрамляющие слеши не нужны. Команда `:hint` показывает подсказку, `:quit` завершает игру. При неверном результате игра покажет входные данные, ожидаемый и фактический результат. Ошибка синтаксиса появится отдельным сообщением. Попытки можно повторять. Скрытые примеры показываются только как контрпримеры.

| Глава | Раунды | Запуск отдельно |
| --- | --- | --- |
| След у проходной | Проверка пропуска через `re.fullmatch`, поиск номеров дел среди дат и обычных чисел через `re.finditer` | `python -X utf8 main.py --chapter passes` |
| Архивный журнал | Маскирование кодов через `re.sub`, разделение журнала через `re.split` | `python -X utf8 main.py --chapter report` |

## Автоматические тесты

```text
python -X utf8 -m unittest discover -v
```

В тестах есть примеры решений. Они проверяют альтернативные шаблоны, скрытые контрпримеры, ошибки компиляции, выдачу подсказок и улик, повторные попытки и прохождение игры через консоль.

## Структура

- `main.py` выводит задания и управляет попытками, уликами и переходами.
- `rounds.py` задаёт интерфейс `Round.check(pattern) -> (success, message)`. Он компилирует шаблон и сравнивает результат операции с ожидаемым значением на открытых и скрытых примерах.
- `passes.py` и `report.py` содержат по одной главе и экспортируют `CHAPTER`. В главе определены тексты, операции, примеры и улики.
- `tests/test_passes.py` и `tests/test_report.py` проверяют главы, а `tests/test_game.py` проверяет общий сценарий.

## Участники и командная работа

| Участник | Глава | Файлы | Ветка |
| --- | --- | --- | --- |
| Вписать имя и GitHub-логин первого участника | След у проходной | `passes.py`, `tests/test_passes.py` | `feature/passes` |
| Вписать имя и GitHub-логин второго участника | Архивный журнал | `report.py`, `tests/test_report.py` | `feature/report` |

1. Создайте общий репозиторий GitHub, пригласите второго участника с правом записи. Если начинаете с общей основы, поместите в `main` файлы `rounds.py`, `main.py`, `.gitignore`, README и пустой `tests/__init__.py`. Пока обе главы в разработке, проверяйте доступную главу через `--chapter`. Общий тест `tests/test_game.py` добавьте после появления обеих глав. Если импортируете MVP целиком, сохраните его как исходную версию и сделайте дальнейшие доработки глав в своих ветках. Укажите, какую работу выполнил каждый.
2. Каждый участник клонирует репозиторий и создаёт свою ветку от актуальной `main`. Пример для первой главы:

   ```text
   git switch main
   git pull --ff-only origin main
   git switch -c feature/passes
   ```

3. Доработайте свою главу и её тесты. Проверьте их, затем добавьте изменённые файлы, сделайте коммит и отправьте ветку. Пример для первой главы:

   ```text
   python -X utf8 main.py --chapter passes
   python -X utf8 -m unittest tests.test_passes -v
   git add passes.py tests/test_passes.py
   git commit -m "Доработать раунды проходной и их тесты"
   git push -u origin feature/passes
   ```

4. Откройте pull request в `main` и назначьте второго участника проверяющим. Опишите выполненные изменения и команды проверки. Проверяющий запускает главу из ветки PR, вводит ошибочный и правильный шаблоны и оставляет комментарий с фактическими результатами. Если нужны исправления, автор добавляет их в ту же ветку.
5. После ревью объедините PR, обновите локальную `main`, запустите весь набор тестов и пройдите игру до финала.
